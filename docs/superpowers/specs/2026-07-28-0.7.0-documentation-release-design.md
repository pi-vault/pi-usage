# 0.7.0 Documentation Release Design

## Purpose

Prepare `@pi-vault/pi-usage` for the next package release by documenting the behavior already present on the release branch, recording the release notes, and aligning the package version with the planned `0.7.0` release.

This is release preparation only. It does not add runtime behavior, create a Git tag, publish the package, or push to a remote.

## Current baseline

- Current package version: `0.6.0`.
- The branch contains the post-`v0.6.0` StepFun and Insights changes, including:
  - StepFun browser-session authentication through `platform.stepfun.ai`.
  - Step Plan monthly Credit tracking.
  - Compact all-time Insights category navigation.
  - Current request-contract and open-dashboard update fixes.
- The working tree is clean.
- The public usage flow remains `/usage`, `/usage:refresh`, exported events, and exported types.
- Package metadata declares Node.js `>=24.15.0`, peer dependencies on `@earendil-works/pi-coding-agent` and `@earendil-works/pi-tui`, and the existing package exports.

## Release decision

Target version: `0.7.0`.

Changelog date: `2026-07-28`.

The minor version is appropriate because the branch includes a user-facing StepFun authentication migration and new compact Insights navigation, while the existing command and exported API surface remains compatible.

## Scope

Modify exactly these tracked files:

- `package.json`
  - Change only the package `version` field from `0.6.0` to `0.7.0`.
  - Preserve dependencies, scripts, exports, engines, `pi` extension metadata, and package file list.
- `CHANGELOG.md`
  - Replace the current `## [Unreleased]` heading with `## [0.7.0] - 2026-07-28`.
  - Preserve the existing release-note categories and factual content for the post-`0.6.0` changes.
  - Keep historical `0.6.0` and older entries unchanged.
- `README.md`
  - Rewrite the document in a targeted, usage-first structure while retaining useful screenshots and provider setup details.
  - Remove stale references to an Insights period selector and StepFun username/password or legacy `.com` behavior.

Do not modify runtime source, tests, screenshots, dependency metadata, lockfile contents, Git tags, or remote branches.

## README design

Keep the existing package badges and summary, then organize the content in this order:

1. **Install**
   - Install with `pi install npm:@pi-vault/pi-usage`.
   - Reload Pi with `/reload`.
2. **Use it**
   - Explain `/usage` as the normal dashboard entry point using cached live data when available.
   - Explain `/usage:refresh` as the explicit live-provider refresh and local-history rescan command.
3. **Dashboard**
   - **Usage Statistics:** period selection, expandable provider/model rows, sessions, messages, cost, and token metrics.
   - **Current Usage:** provider selection, quota/balance display, and `live`, `cached`, `stale`, `local`, and `unavailable` states; mention StepFun Credits where applicable.
   - **Insights:** all-time local-history breakdowns with left/right category navigation; only populated Projects, Skills, MCP servers, and Cost patterns categories appear, with capped rows and overflow summaries.
   - Retain the existing dashboard screenshots in the corresponding sections.
4. **Keyboard Shortcuts**
   - Document global tab/close controls, Usage Statistics period/row controls, Current Usage provider navigation, and Insights category navigation.
5. **Configuration**
   - Preserve `usage.json` provider-toggle behavior and examples.
   - Preserve provider environment-variable setup for OpenAI/Codex, MiniMax, OpenCode Go, Command Code, and OpenRouter.
   - Document StepFun browser-session setup using `Oasis-Token` and `Oasis-Webid` cookies from `platform.stepfun.ai`, exported as `STEPFUN_TOKEN` and `STEPFUN_WEB_ID`; clearly warn that both are secrets and must not be committed or shared.
6. **Changelog and License**
   - Link to `CHANGELOG.md` and `LICENSE`.

Avoid duplicating a separate Quick Start section and Commands table when the new **Use it** section can explain the same workflow directly.

## Changelog design

The dated `0.7.0` entry will retain these categories and facts:

### Changed

- Pi development ranges changed to `^0.82.0`, with the lockfile resolving both direct Pi packages to `0.82.1`.
- StepFun Step Plan tracking migrated to browser-session credentials on `platform.stepfun.ai` and monthly Credit usage.
- The unsupported Insights period selector replaced with compact all-time category navigation.

### Fixed

- Current StepFun browser request headers and cookie casing.
- Insights category navigation visibility in constrained-width footers.
- Open dashboard synchronization with completed provider and offline-history updates.

### Removed

- StepFun username/password login and legacy `.com` dashboard requests.

Historical release entries will not be rewritten.

## Verification

Run checks in this order:

1. Inspect the diff and assert that only the intended three files changed.
2. Confirm the package version is exactly `0.7.0` and the changelog has exactly one dated `0.7.0` heading.
3. Search `README.md` and `CHANGELOG.md` for stale StepFun username/password, `platform.stepfun.com`, and Insights-period wording.
4. Run `git diff --check`.
5. Run `pnpm check` for lint, typecheck, and the full test suite.
6. Run `pnpm pack:dry-run` and confirm the package still contains the existing public files without credentials or unrelated artifacts.
7. Confirm `git status --short` contains only the planned changes; do not create a tag or push.
